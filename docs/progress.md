## Failed approaches (do not retry)

- Pinning the model through `_meta.claudeCode.options.model` on `session/new` or through `ANTHROPIC_MODEL` in the box: the adapter calls `setModel(models[0])` after start and the run goes to the default model (Opus). Use `"model"` in the project's `.claude/settings.json`.
- Playwright MCP with `--cdp-endpoint http://host.docker.internal:9222`: Chrome rejects any `Host` header that is not an IP address or `localhost`. Use the address the name resolves to inside the box.
- Reading usage or cost from ACP: adapter 0.16.2 drops the CLI's `result` message and never sends `usage_update`. Tail the session transcript in the box instead.
- Writing an MCP tool name from memory or by analogy with another server. `mcp__sentry__list_issues` and `mcp__github__get_pull_request` do not exist: Sentry has no `list_*` tool at all, and GitHub folded `get_pull_request`/`_files`/`_status` into `pull_request_read` with a `method` argument and `update_issue` into `issue_write`. Check the vendor's published tool list, then record it in the surface table the example-bot ratchets read.
- Gating a box's lifecycle on the `running` flag from the container listing. It is a snapshot: right after a `stop`, a container on its way down still reads as running, so `reconnect` skipped `startContainer` and handed back a box that had already exited (`409 container stopped/paused`). `startContainer` and `stopContainer` both swallow 304, so call them unconditionally. **Docker Desktop cannot reproduce this** — the listing flips promptly here and the buggy code passes; only the Linux CI runner shows the window, so a green local integration run is not evidence about a Docker timing question.
- Reading a finite file through `Computer.attach` instead of `readFile`, to bound memory. The port documents `attach` as a long-lived duplex process for a protocol over stdio and **promises nothing about stdout ever ending**; only `readFile` is finite by construction. A fake whose attached stream stays open — which is what `tail -F`, the only thing ever attached for a transcript, actually does — hangs the caller, and `DockerComputer.wait()` cannot rescue it because it resolves only after the streams close. In teardown this is worse than the problem it solves: totality guards against a step throwing, not against a step hanging, and a hang means the event stream never closes at all.
- Running the `validate` CLI from source with `node --experimental-strip-types`: `contracts` is imported through its `exports` map and its source uses `.js` specifiers, which Node does not rewrite. The CLI is built to `dist/cli` and the `validate` script builds its dependency chain first.

## Open questions for the owner

- Approval patterns match tool names, not arguments, and vendors increasingly fold several verbs behind one tool with a `method` argument — GitHub's `label_write` does create, update and delete, `issue_write` carries a `state` — so a `deny: create_*` prefix rule does not actually stop creation, and a prefix deny silently assumes one verb per tool name. Two of the example bots run into that: `pr-triage` must label through `issue_write`, the same tool that closes, so "label but never close" is enforced by the approval the person gives, not by `deny`; `inbox-briefing` needs `browser_tabs` to find the webmail tab, and the same tool closes tabs, so it sits under `require`. Is an argument-aware pattern (`Bash(git push --force*)`, `browser_tabs(close)`) worth adding to the format, or does the approval prompt stay the place where the person sees the argument?
- A `catalog:` reference cannot carry `args` or `env`, so a bot cannot ask the catalog's Playwright server for `--cdp-endpoint` itself; `inbox-briefing` relies on `browser: host-cdp` and the host adding the server with the resolved address (the `mcpServers` option of `toClaudeProjectFiles`, which wins on a name clash). Fine as long as the worker does that; worth a sentence in `docs/bot-format.md` once the worker exists.
- `runCommand` and `readFile` buffer everything the box writes, with no cap. An untrusted box can therefore exhaust the worker's heap by writing to stdout. A cap makes `readFile` of a large workspace file fail, so what the limit should be — and whether `readFile` should stream instead — is a product call, not an implementation one.
- The box has no `host.docker.internal` entry on Linux, so the host's Chrome over CDP is reachable from a box on Docker Desktop but not on a Linux host. Adding `ExtraHosts: ["host.docker.internal:host-gateway"]` fixes it in one line, but it widens what an untrusted box can reach on the host; left out of the provider until the CDP wiring lands and the owner has seen the trade.
- `bots/examples` is a folder under `./bots` that is not a bot. Whatever scans `./bots` for bot folders later has to skip it (or treat a folder without `BOT.md` as not a bot) rather than report it as broken.
